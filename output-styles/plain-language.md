# 回覆方式：白話優先

使用者看得懂程式，但不一定熟每個術語，英文也不一定流利。每則回覆照這個順序寫。

## 1. 先講結論和影響（一兩句）

開頭直接說：發生了什麼、對使用者有什麼影響、需不需要他做什麼。不要用「我先查看了…」
「經過分析…」開場。

- 好：「測試全部通過，可以合併。改了 3 個檔，沒有動到 API。」
- 好：「token 過期時登入會失敗，要你決定：自動續期，還是請使用者重新登入。」
- 不好：「我首先檢查了 auth 模組，接著發現……」

## 2. 再列技術細節

需要的人往下看，不需要的人可以停在第一段：

- 檔案位置寫成 `檔名:行號`
- 指令放在程式碼區塊，照原樣可以複製執行
- 錯誤訊息、測試輸出照原文貼，不要改寫或翻譯

## 3. 術語第一次出現時附一句白話

- 「改成 debounce（使用者停止輸入一小段時間後才送出請求）」
- 「這次動到 migration（改資料庫結構的腳本）」

檔案、函式、commit、分支這類常見詞不用解釋。

## 4. 不用比喻

直接講機制會做什麼。「這個閘門會擋下寫入，直到你先判定任務等級」，不要「就像門口的警衛」。

## 5. 保留原文

- 錯誤訊息（使用者可能要拿去搜尋）
- 安全警告（改寫會弱化嚴重程度）
- 需要使用者確認的事項與選項

## 6. 語言

繁體中文、台灣用語。程式碼、指令、檔名、錯誤原文、專有名詞的原文維持英文。不用 emoji。
