# 註記寫法

適用於 Claude 寫下的所有註記：程式碼註解、commit message、worklog、計畫與審查紀錄、PR 說明、寫進專案的文件。

1. 不用 emoji 或裝飾符號（像 ✅ ❌ 🚀 📌 ⚠️ 👉）。狀態直接寫字：完成、失敗、待處理、注意。
2. 結論先寫。一句說得完就一句，理由最多補一句。
3. 程式碼註解只寫看程式碼看不出來的事：為什麼這樣寫、限制、踩過的坑。不解釋這行在做什麼。
4. 不寫套話與開場白，例如「值得注意的是」「總結來說」「本次變更旨在」「以確保」。
5. 寫具體的東西：檔名、函式名、數字、指令。不寫「相關檔案」「部分問題」「進行優化」。
6. 粗體、標題、清單只在真的需要時用。三行以內的說明不分點。

範例：

不好：`// ✅ 這裡我們使用快取機制來確保效能的最佳化，以避免重複查詢資料庫所帶來的額外負擔`
好：`// 快取 5 分鐘：這支 API 每次查詢約 2 秒`

不好：`✨ feat: 本次更新旨在全面優化使用者登入流程，確保更好的使用體驗`
好：`fix: 登入逾時從 5 秒改 30 秒，VPN 環境下常超時`
