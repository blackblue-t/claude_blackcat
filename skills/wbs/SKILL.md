# WBS 格式與更新規則

WBS 是**打開就能掌握專案狀態**的文件，不是工作日誌。檔案：

- `.claude/taskmaster-data/wbs.md`：進行中的里程碑
- `.claude/taskmaster-data/wbs-archive.md`：已完成的里程碑（多一個「實際」欄）
- `.claude/taskmaster-data/.current-task`：目前在做的任務編號（一行），時間追蹤靠它歸帳

判準：除了「任務」欄寫完整名稱，其他格子都只寫一行。

## 1. wbs.md 版面

```markdown
# WBS - <專案名稱>

最後更新：YYYY-MM-DD ・ 開發情境：mvp ・ 總進度：████████░░ 82%（94 / 115）
專案描述：<一句話>

## 現況
<!-- 本區由指令重算，勿手改 -->
| 里程碑 | 進度 | 狀態 | 目標日 |
|---|---|---|---|
| M2 會員系統 | ██░░░ 3/8 | 進行中 | 11-15 |
| M3 報表 | ░░░░░ 0/5 | 待處理 | 11-30 |
| M1 | 已歸檔 12 項 | 完成 | - |

- 進行中：2.2 登入流程
- 阻塞：2.4 第三方登入 - 等客戶提供 OAuth 金鑰（R1）
- 下一個：2.3 忘記密碼

## M2 會員系統
| # | 任務 | 狀態 | 優先 | 依賴 | 預估 | 連結 |
|---|---|---|---|---|---|---|
| 2.1 | 建立會員資料表 | 完成 10-20 | 高 | - | 2h | [計畫](../plans/archive/2026-10-18-member-table.md) |
| 2.2 | 登入流程 | 進行中 | 高 | 2.1 | 4h | [計畫](../plans/2026-10-25-login.md) |
| 2.3 | 忘記密碼 | 待處理 | 中 | 2.2 | 3h | - |
| 2.4 | 第三方登入 | 阻塞 | 中 | 2.2 | 5h | R1 |

## 風險與阻塞
| ID | 風險／阻塞 | 影響 | 緩解 | 相關任務 |
|---|---|---|---|---|
| R1 | 客戶未提供 OAuth 金鑰 | 2.4 無法開始 | 先做帳密登入 | 2.4 |

## 不做（non-goals）
- <這個版本刻意不包含的東西>
```

## 2. 欄位規則

| 欄位 | 寫什麼 | 不寫什麼 |
|---|---|---|
| `#` | `<組>.<序>`，例 `2.3`。**編號永不重用**，含已歸檔的 | - |
| 任務 | 完整名稱（動詞＋對象），與計畫標題一致 | 做法、驗收條件（那是計畫檔） |
| 狀態 | `完成 MM-DD`／`進行中`／`待處理`／`阻塞`／`跳過` | 原因、百分比、數據 |
| 優先 | `高`／`中`／`低` | - |
| 依賴 | 任務編號，逗號分隔；無則 `-` | 技術依賴 |
| 預估 | `4h`、`0.5h` | 實際耗時（時間紀錄會算） |
| 連結 | `[計畫](../plans/…)`、`[任務](../tasks/…)`、風險 ID；多個用 ` ・ ` 分隔；無則 `-` | 任何說明文字 |

連結路徑相對於 `.claude/taskmaster-data/`。

**連結欄的生命週期：**

| 時機 | 誰 | 連結欄 |
|---|---|---|
| 新建任務 | `/task-init`、`/task-add` | `-` |
| 計畫確認 | `/plan` | 加 `[計畫](../plans/<檔名>)`，計畫檔 frontmatter 寫 `wbs: <編號>` |
| 匯出並行任務 | `/plan` | 加 `[任務](../tasks/<檔名>)`，任務檔 frontmatter 寫 `wbs: <編號>` |
| 標阻塞 | 標記者 | 加風險 ID，並在「風險與阻塞」表新增或沿用 |
| 計畫歸檔 | `/commit`、`/verify` | 改指 `../plans/archive/…`（漏改會變死連結） |

## 3. 狀態怎麼變

| 事件 | 誰 | 動作 |
|---|---|---|
| 開始做 | `/task-next`，或 `/go`、`/plan` 對應到 WBS 某列時 | 該列改 `進行中`，寫 `.current-task` |
| 做完並提交 | `/commit`（計畫或任務檔帶 `wbs:` 的） | 該列改 `完成 MM-DD`，清掉 `.current-task` |
| 卡住 | 任何人 | 改 `阻塞`＋風險 ID |
| 決定不做 | 使用者 | 改 `跳過` |

## 4. 「現況」區的重算規則

任何指令寫完任務列之後，**同一次寫入**裡一併重算檔頭總進度與現況區。

| 項目 | 怎麼算 |
|---|---|
| 總進度 | 分子＝完成數（含已歸檔），分母＝全部任務數 − 跳過數（含已歸檔）。10 格長條，填滿格數＝round(比例 × 10) |
| 里程碑進度 | 同上，5 格長條＋`完成/總數`；已歸檔的寫 `已歸檔 N 項` |
| 里程碑狀態 | 全部完成或跳過→`完成`；有進行中，或已有完成但未全完成→`進行中`；其餘有阻塞→`阻塞`；否則`待處理` |
| 目標日 | **唯一不是算出來的欄位**，使用者定，重算時沿用 |
| 進行中／阻塞／下一個 | 各列最多 3 項，超過寫「等 N 項」；沒有寫 `-`。「下一個」照 `/task-next` 的選法 |

## 5. 長內容該去哪裡

| 想寫進格子的 | 改放到 | WBS 留什麼 |
|---|---|---|
| 驗證數據、測試結果 | 計畫檔的驗收段落或 worklog | 連結 |
| 進度細節、commit hash | worklog（`/commit` 歸檔到 `.claude/worklog-archive/`） | 不留 |
| 選型與理由 | 計畫檔或 ADR | 必要時連結 |
| 阻塞原因 | 本檔「風險與阻塞」表 | 狀態 `阻塞`＋風險 ID |
| 主機、帳號、金鑰 | `.env.example` 或部署文件（**秘密不進任何 md**） | 不留 |

## 6. 歸檔

里程碑全部完成或跳過時，`/task-status` 提議把整段搬到 `wbs-archive.md`：

```markdown
## M1 MVP（2026-09-01 ~ 2026-10-10）・ 12 項 ・ 預估 24.5h ／ 實際 27h
| # | 任務 | 狀態 | 優先 | 依賴 | 預估 | 實際 | 連結 |
```

「實際」取自時間紀錄（`/time-log --by-task` 的算法），沒有資料寫 `-`。歸檔的跳過任務不列入
「已歸檔 N 項」。

## 7. 舊格式

`/task-init` 舊版寫的 WBS（有 emoji 狀態、`備註` 欄、沒有現況區）：狀態對照
（完成／進行中／待處理／阻塞／跳過）轉成文字，備註欄的長內容照第 5 節搬走，不能丟資料，
再補上現況區。改之前先給使用者看轉換結果。
