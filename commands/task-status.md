# 專案進度（/task-status）

格式、重算與歸檔規則以 `wbs` skill 為準。沒有 WBS → 建議 `/task-init`。

## 流程

1. 讀 `wbs.md`（和 `wbs-archive.md` 的已歸檔數），**先重算現況區**；跟檔案裡的不一樣就寫回
   （有人手改過表格時會這樣）。
2. 讀時間紀錄（算法同 `/time-log --by-task`），算每個里程碑的預估合計與實際合計。
3. 輸出：

```
專案進度：████████░░ 82%（94 / 115）

里程碑            進度        預估    實際    目標日   判斷
M2 會員系統       ██░░░ 3/8   18h     11h     11-15   照目前速度 11-19 完成，會晚 4 天
M3 報表           ░░░░░ 0/5   12h     -       11-30   -

進行中：2.2 登入流程（預估 4h，已花 5h10m）
阻塞：  2.4 第三方登入 - 等客戶提供 OAuth 金鑰（R1）
下一個：2.3 忘記密碼
```

4. **判斷欄**：
   - 有目標日、有實際資料時：剩餘預估 ×（已完成任務的實際／預估比）÷ 近 7 天平均每日工時
     ＝預計還要幾天，跟目標日比
   - 單一任務實際超過預估 1.5 倍 → 列出來，問要不要拆或調整預估
   - 資料不夠（完成不到 3 項）就寫「資料不足」，不要硬算

## 歸檔

有里程碑全部 `完成`／`跳過` → 問使用者要不要歸檔。同意就照 `wbs` skill 第 6 節搬到
`wbs-archive.md`，補「實際」欄，現況區改 `已歸檔 N 項`。

## 舊格式

讀到舊版 WBS（emoji 狀態、`備註` 欄）→ 照 `wbs` skill 第 7 節提議轉換，使用者確認才改。
